# Emby integration

On Apple TV, iPhone, or Android, open Sources as Admin, choose Emby, and enter the complete HTTPS address of a server you can already reach from the device. Use the Emby user account that has access to the movies, shows or photos you want. MediaVault saves one selected library per source. Use Edit to rename or reconnect a source. Reconnect with the same account and library to keep existing MediaVault history.

Keep Emby server sign-in separate from MediaVault household profiles. New libraries start hidden from viewers. An Admin can explicitly grant a profile access to the library in household settings. The profile’s movie and show rating limits, Watchlist and playback history continue to apply. The source account sends playback progress to Emby for the MediaVault Admin session only.

Compatible Emby videos play directly and seek over authenticated byte ranges. MediaVault can fall back to an authenticated HLS encoding when Emby offers one. It supports native embedded tracks and can read external text subtitles from the negotiated Emby media source. Existing SMB sidecars and SubDL search are also available for their supported sources and matched titles. Android displays primary Emby artwork for movie cards, and Apple TV and iPhone display artwork for movie and show cards. Photo libraries open through the normal protected photo viewer.

The clients use the public Emby REST API and platform networking and playback libraries. MediaVault does not bundle the Emby server, Emby SDK or Emby assets. The optional local test downloads the official server image and discards its synthetic media and credentials at the end of the run. [Emby REST API](https://dev.emby.media/doc/restapi/) [Subtitle endpoint](https://dev.emby.media/doc/restapi/Subtitles.html) [Image service](https://dev.emby.media/reference/RestAPI/ImageService.html)

## Verification

- On a Linux cloud checkout with Docker, ffmpeg and the Android build tools, run `python3 scripts/test_emby_fixture.py`. It creates a fresh account, movie, English SRT and JPEG using the pinned official Emby image and exercises sign-in, library discovery, import paging, range reads, photo and subtitle retrieval, playback progress, HLS playlist and segment reads, encoding cleanup and sign-out.
- The Android TV runtime job exercises the HTTPS setup form, Room import, Keystore restoration, revoking a household grant, and seeking to a rendered video frame.
- Apple TV and iPhone simulator jobs require `EmbyNativePlaybackTests/testEmbyImportsRendersAndSeeksDirectAndHLSOverHTTPS`. The test signs in to the disposable TLS fixture, verifies whole-library household authorization, imports a two-page catalog, and checks decoded AVPlayer frames before and after an exact seek for both the direct MP4 and the authenticated HLS stream. It checks the server's English subtitle after the HLS seek. The same loopback listener and generated HLS media support the Jellyfin fixture.
- A focused run on a Mac needs Xcode, XcodeGen, ffmpeg, and a disposable simulator. Start `scripts/start_jellyfin_tvos_fixture.sh` with a new temporary directory, trust its `fixture.cer` only in that simulator, and run the named XCTest with the applicable simulator scheme. The unsigned tvOS CI job verifies the production build independently.
- Signed distribution and verification on physical Apple TV and iPhone devices require separate access. Apple decides approval after review of the submitted build.
